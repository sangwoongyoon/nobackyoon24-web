# 홈페이지 글 올리기 지침 (블로그 자동화용)

> 이 문서는 블로그 자동화(seasen2)가 **네이버 블로그 글 1개 → 홈페이지(nobackyoon24.com) 글 1개**로 변환해서 업로드할 때 따르는 규칙이다.
> 블로그 글을 그대로 복사하지 않는다. 홈페이지 버전은 **짧고, 숫자 위주이며, 구글·AI 검색이 인용하기 좋은 구조**로 다시 쓴다.

---

## 0. 기본 정보

| 항목 | 값 |
|---|---|
| 저장소 | `github.com/sangwoongyoon/nobackyoon24-web` |
| 기본 브랜치 | `main` (push 하면 Vercel이 실제 사이트에 자동 배포) |
| 데모 브랜치 | `preview/글슬러그` (push 하면 Vercel 미리보기 주소 생성, 실제 사이트 영향 없음) |
| 글 폴더 | 매각사례 `content/cases/` · 칼럼 `content/columns/` · 부동산뉴스 `content/news/` |
| 이미지 폴더 | `public/images/<게시판>/<슬러그>/` |
| 양식 | 각 글 폴더의 `_양식.md` |

---

## 1. 입력 (블로그 자동화가 이미 갖고 있는 것)

1. 블로그 본문 텍스트 (제목 포함)
2. 물건내역 이미지 (표 이미지 → **OCR로 숫자 추출**)
3. 현장 사진 (코너/전경, 거리, 측면, 후면)
4. 썸네일 이미지

**사용하지 않는 이미지:** Key Point 배너, 전화번호/카카오톡 CTA 배너, 프로필 배너.
같은 내용이 홈페이지에서는 글자와 버튼으로 이미 들어가 있다.

---

## 2. 어느 게시판에 올릴지

| 블로그 글 성격 | 게시판 | 폴더 |
|---|---|---|
| 시중 실거래 / 매각 사례 소개 | 매각사례 | `content/cases/` |
| 투자·세금·법인·매입전략 등 정보글 | 칼럼 | `content/columns/` |
| 기사·정책·금리 등 뉴스 해설 | 부동산뉴스 | `content/news/` |

※ 본인이 직접 계약한 실적은 여기 올리지 않는다 (기존 `프로젝트` 탭 = `src/data/projects.js`).

---

## 3. 파일 이름 (= 주소)

- 영문 소문자, 숫자, 하이픈(-)만 사용. 한글·공백 금지.
- 형식: `동이름-핵심특징-금액` 예) `junggok-7line-corner-32eok.md`
- 주소는 `nobackyoon24.com/cases/junggok-7line-corner-32eok` 가 된다.
- 이미 같은 이름의 파일이 있으면 뒤에 `-2` 를 붙인다.

---

## 4. 이미지 처리

1. `public/images/<게시판>/<슬러그>/` 폴더 생성
2. 모든 이미지를 **WebP, 가로 최대 1200px, 품질 82** 로 변환
3. 파일 이름은 영문으로 고정:
   - `thumbnail.webp` (목록 카드용 썸네일)
   - `corner.webp` (대표 사진 = 코너/정면 전경)
   - `street.webp` (앞 도로)
   - `side.webp` (측면)
   - `rear.webp` (후면)
   - 그 외: `photo-1.webp`, `photo-2.webp` …
4. 본문에 넣을 때 **alt(사진 설명)를 반드시 한국어로 구체적으로** 쓴다.
   - 좋은 예: `![중곡동 24-1 건물 측면 – 1층 정육점과 차고](/images/cases/junggok-24-1/side.webp)`
   - 나쁜 예: `![사진](...)`, `![image](...)`

## 6. 작성 규칙 (구글·AI 검색 최적화)

1. **결론 먼저.** 첫 문장에 금액·평당가 등 숫자로 답한다.
2. **제목:** `지역명 + 물건유형 + 매매/매각 + 금액 – 핵심특징` (60자 이내). 사람들이 검색하는 단어로 시작.
3. **description:** 150자 내외, 지역·금액·평당가·핵심스펙을 한 문단에.
4. **summary(핵심 요약):** 4줄, 각 줄에 숫자 포함. AI 개요가 가장 많이 인용하는 부분.
5. **본문 분량:** 500~800자. 블로그처럼 길게 쓰지 않는다. 문단은 2~3문장.
6. **소제목은 질문형** (`~얼마에 거래됐나?`, `왜 거래됐나?`).
7. **표를 1개 이상** 넣는다 (입지 포인트, 비교 등).
8. **FAQ 3개.** 질문에 지역명 포함, 답 첫 문장에 숫자.
9. **tags 5개:** `동이름 빌딩매매`, `동이름 + 물건유형`, `노선 역세권 상가`, `물건특징 매매`, `구이름 꼬마빌딩` 패턴.
10. 문체는 `~입니다/~습니다`. 블로그식 인사·줄바꿈("안녕하세요!", "포스팅 시작하겠습니다")은 모두 제거.
11. **블로그에 없는 사실은 절대 만들지 않는다.** 숫자는 블로그 본문·물건내역 이미지에 있는 것만 사용하고, 계산값(평당가 등)만 추가 허용.
12. 전화번호·카카오톡 ID는 본문에 넣지 않는다 (사이트 하단에 이미 있음).

### 칼럼 / 부동산뉴스 차이
- 칼럼: `deal` 없음. 제목은 질문형 (`법인으로 빌딩 사면 세금이 얼마나 줄어들까?`). `category` 예: 매입전략 / 매각전략 / 세금·법인 / 시장분석.
- 부동산뉴스: `deal` 없음, **`source`(언론사명·URL·날짜) 필수**. 기사 문장 복사 금지, 자기 말로 요약 + 해설.

## 7. 업로드 순서 (데모 → 최종)

```bash
# 저장소 최신화
git checkout main && git pull

# 1) 데모 브랜치 생성
git checkout -b preview/<슬러그>

# 2) 글 파일 + 이미지 추가 (draft: false 로 작성)
#    content/<게시판>/<슬러그>.md
#    public/images/<게시판>/<슬러그>/*.webp

# 3) 데모 올리기
git add content public/images
git commit -m "글 추가: <제목>"
git push -u origin preview/<슬러그>
# → 1~2분 뒤 Vercel 미리보기 주소 생성 (GitHub 커밋 옆 체크표시 → Vercel → Details)

# 4) 사용자 확인 후 "최종 적용" 지시가 오면
git checkout main
git merge preview/<슬러그>
git push origin main
# → 1~2분 뒤 nobackyoon24.com 반영, sitemap.xml 자동 갱신
```

- `draft: true` 인 글은 실제 사이트에서 숨겨진다. 공개하려면 `draft: false`.
- 수정할 때는 같은 파일을 고치고 `updated: YYYY-MM-DD` 를 추가한다 (최신성 신호).
- 업로드 전 `npm run build` 가 통과하는지 확인 (실패 시 YAML 따옴표·들여쓰기 확인).
